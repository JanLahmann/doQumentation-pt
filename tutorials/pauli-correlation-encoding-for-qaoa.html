Codificação de correlação de Pauli para reduzir requisitos de max-cut

Estimativa de uso: 35 minutos em um processador Eagle r3 (NOTA: Esta é apenas uma estimativa. Seu tempo de execução pode variar.)

Resultados de aprendizagem​

  • Compreender os princípios teóricos por trás da Codificação de Correlação de Pauli (PCE), incluindo como strings de Pauli de múltiplos corpos permitem a compressão polinomial de problemas de otimização clássicos.

  • Implementar a PCE na prática para codificar e resolver tarefas de otimização em larga escala em hardware quântico de curto prazo.

Pré-requisitos​

  • Algoritmos quânticos variacionais

  • QAOA e max-cut

Contexto​

Este tutorial apresenta a Codificação de Correlação de Pauli (PCE) [1], uma abordagem projetada para codificar problemas de otimização em qubits com maior eficiência para computação quântica. A PCE mapeia variáveis clássicas em problemas de otimização para correlações de matriz de Pauli de múltiplos corpos, resultando em uma compressão polinomial dos requisitos de espaço do problema. Ao empregar PCE, o número de qubits necessários para codificação é reduzido, tornando-a particularmente vantajosa para dispositivos quânticos de curto prazo com recursos limitados de qubits. Além disso, é demonstrado analiticamente que a PCE inerentemente mitiga platôs áridos, oferecendo resiliência super-polinomial contra este fenômeno. Este recurso integrado permite desempenho sem precedentes em solucionadores de otimização quântica.

Visão geral​

A abordagem PCE consiste em três etapas principais, conforme ilustrado na Figura 1 de [1] a seguir:

  1. Codificar o problema de otimização em um espaço de correlação de Pauli.
  2. Resolver o problema usando um solucionador de otimização quântico-clássico.
  3. Decodificar a solução de volta para o espaço de otimização original. A abordagem PCE é adaptável a qualquer solucionador de otimização quântica capaz de processar matrizes de correlação de Pauli. Na Figura 1 de [1], o problema de max-cut é usado como exemplo para ilustrar a abordagem PCE. O problema de max-cut com m=9m=9m=9 nós é codificado em um espaço de correlação de Pauli, representando o problema de otimização como uma matriz de correlação — especificamente, correlações de matriz de Pauli de dois corpos através de n=3n=3n=3 qubits (Q1,Q2,Q3)(Q_1, Q_2, Q_3)(Q1​,Q2​,Q3​). As cores dos nós indicam a string de Pauli usada para cada nó codificado. Por exemplo, o nó 1, que corresponde à variável binária x1x_1x1​, é codificado pelo valor esperado de Z1⊗Z2⊗I3Z_1 \otimes Z_2 \otimes I_3Z1​⊗Z2​⊗I3​, enquanto x8x_8x8​ é codificado por I1⊗Y2⊗Y3I_1 \otimes Y_2 \otimes Y_3I1​⊗Y2​⊗Y3​. Isso corresponde a comprimir as mmm variáveis do problema em n=O(m1/2) n = O(m^{1/2})n=O(m1/2) qubits. De forma mais ampla, correlações de kkk corpos permitem compressões polinomiais de ordem kkk, com k>1k>1k>1. O conjunto de Pauli escolhido compreende três subconjuntos de strings de Pauli mutuamente comutativas, permitindo que todas as mmm correlações sejam estimadas experimentalmente com apenas três configurações de medição.

Uma função de perda L\mathcal{L}L de valores esperados de Pauli que imita a função objetivo original do max-cut é construída. A função de perda é então otimizada usando um solucionador de otimização quântico-clássico, como o Variational Quantum Eigensolver (VQE).

Uma vez que a otimização está completa, a solução é decodificada de volta para o espaço de otimização original, produzindo a solução ótima do max-cut.

Requisitos​

Antes de iniciar este tutorial, certifique-se de ter o seguinte instalado:

  • Qiskit SDK v1.0 ou posterior, com suporte para visualização
  • Qiskit Runtime v0.22 ou posterior (pip install qiskit-ibm-runtime)
  • Addon do Qiskit Optimization Mapper (pip install qiskit-addon-opt-mapper)

def make_cut_evaluator(problem):
    """Return a function that maps a 0/1 node assignment to its cut value.

    The objective of the max-cut ``OptimizationProblem`` is the cut value
    itself, and ``problem.objective.evaluate`` computes it for one
    assignment. The swap search in Step 4 evaluates one candidate
    assignment per edge, so pull the objective's coefficients out once
    and evaluate them as a sparse matrix product instead.
    """
    quadratic = problem.objective.quadratic.coefficients.tocsr()
    linear = problem.objective.linear.to_array()
    constant = problem.objective.constant

    def evaluate_cut(bits):
        x = np.asarray(bits, dtype=float)
        return int(round(constant + linear @ x + x @ (quadratic @ x)))

    return evaluate_cut

Passo 1: Mapear entradas clássicas para um problema quântico​

O problema de max-cut​

O problema de max-cut é um problema de otimização combinatória que é definido em um grafo G=(V,E)G = (V, E)G=(V,E), onde VVV é o conjunto de vértices e EEE é o conjunto de arestas. O objetivo é particionar os vértices em dois conjuntos, SSS e V∖SV \setminus SV∖S, de modo que o número de arestas entre os dois conjuntos seja maximizado. Para a descrição detalhada do problema de max-cut, consulte o tutorial Algoritmo de otimização aproximada quântica. O problema de max-cut também é usado como exemplo no tutorial Técnicas avançadas para QAOA. Nesses tutoriais, o algoritmo QAOA é usado para resolver o problema de max-cut.

Grafo → problema de otimização​

Codificamos o grafo com 100 nós em correlações de matriz de Pauli de dois corpos através de nove qubits (veja a explicação abaixo). O grafo é representado como uma matriz de correlação, onde cada nó é codificado por uma string de Pauli. O sinal do valor esperado da string de Pauli indica a partição do nó. Por exemplo, o nó 0 é codificado por uma string de Pauli, ∏0=I8⊗...I2⊗X1⊗X0\prod_0 = I_{8} \otimes ... I_2 \otimes X_1 \otimes X_0∏0​=I8​⊗...I2​⊗X1​⊗X0​. O sinal do valor esperado desta string de Pauli indica a partição do nó 0. Definimos uma codificação de correlação de Pauli (PCE) relativa a ∏\prod∏ como

xi≔sgn(⟨∏i⟩),x_i \coloneqq \textit{sgn}(\langle\prod_i \rangle),xi​:=sgn(⟨∏i​⟩),

onde xix_ixi​ é a partição do nó iii e ⟨∏i⟩≔⟨ψ∣∏i∣ψ⟩\langle \prod_i \rangle \coloneqq \langle \psi |\prod_i| \psi \rangle ⟨∏i​⟩:=⟨ψ∣∏i​∣ψ⟩ é o valor esperado da string de Pauli codificando o nó iii sobre um estado quântico ∣ψ⟩|\psi \rangle∣ψ⟩. Agora, vamos codificar o grafo em um Hamiltoniano usando PCE. Dividimos os nós em três conjuntos: S1S_1S1​, S2S_2S2​ e S3S_3S3​. Então, codificamos os nós em cada conjunto usando as strings de Pauli com XXX, YYY e ZZZ, respectivamente. Precisamos extrair uma relação entre o número de nós e qubits necessários para codificar todos os nós. Usando todas as permutações possíveis para a codificação, obtemos:

m=3(nk).m=3\binom{n}{k}.m=3(kn​).

Neste exemplo consideramos k=2k=2k=2, portanto,

m=32n(n−1).m = \frac{3}{2} n(n-1).m=23​n(n−1).

Portanto, o número de qubits nnn necessários para expressar um certo número de nós mmm é:

n=⌈1+1+83m2⌉.n = \left\lceil \frac{1 + \sqrt{1 + \tfrac{8}{3}m}}{2} \right\rceil.n=​21+1+38​m​​​.

Observe que o símbolo ⌈⋅⌉\lceil \cdot \rceil⌈⋅⌉ representa a função teto, que arredonda qualquer número real para cima até o próximo inteiro. Isso garante que o número de qubits seja um inteiro.

def build_pauli_correlation_encoding(pauli, node_list, n, k=2):
    pauli_correlation_encoding = []
    for idx, c in enumerate(combinations(range(n), k)):
        if idx >= len(node_list):
            break
        paulis = ["I"] * n
        paulis[c[0]], paulis[c[1]] = pauli, pauli
        pauli_correlation_encoding.append(("".join(paulis)[::-1], 1))

    hamiltonian = []
    for pauli, weight in pauli_correlation_encoding:
        hamiltonian.append(SparsePauliOp.from_list([(pauli, weight)]))

    return hamiltonian

pauli_correlation_encoding_x = build_pauli_correlation_encoding(

)
pauli_correlation_encoding_z = build_pauli_correlation_encoding(

Função de perda​

Para a função de perda L\mathcal{L}L, usamos uma relaxação da função objetivo do max-cut conforme descrito em [1], que é definida como V(x)≔∑(i,j)∈EWi,j(1−xixj)\mathcal{V}(\mathbf{x}) \coloneqq \sum_{(i, j) \in E} W_{i, j}(1-x_i x_j)V(x):=∑(i,j)∈E​Wi,j​(1−xi​xj​). Aqui, Wi,jW_{i, j}Wi,j​ denota o peso da aresta (i,j)(i, j)(i,j), e xix_ixi​ representa a partição do nó iii. A função de perda L\mathcal{L}L é dada por:

L≔∑(i,j)∈EWi,jtanh(α⟨∏i⟩)tanh(α⟨∏j⟩)+L(reg)\mathcal{L}\coloneqq \sum_{(i, j) \in E} W_{i, j} \text{tanh} (\alpha \langle\prod_i \rangle) \text{tanh} (\alpha \langle\prod_j \rangle) + \mathcal{L}^{(\text{reg})}L:=∑(i,j)∈E​Wi,j​tanh(α⟨∏i​⟩)tanh(α⟨∏j​⟩)+L(reg),

onde a função objetivo do max-cut é substituída pelas tangentes hiperbólicas suaves dos valores esperados das strings de Pauli codificando os nós. O termo de regularização L(reg)\mathcal{L}^{(\text{reg})}L(reg) e o fator de reescala α\alphaα, proporcional ao número de qubits, são introduzidos para melhorar o desempenho do solucionador.

O termo de regularização é definido como:

L(reg)\mathcal{L}^{(\text{reg})}L(reg) é definido como L(reg)≔βν[1m∑i∈Vtanh(α⟨∏i⟩)2]2\mathcal{L}^{(\text{reg})} \coloneqq \beta \nu \lbrack \frac{1}{m} \sum_{i \in V} \text{tanh} (\alpha \langle\prod_i \rangle)^2 \rbrack ^2L(reg):=βν[m1​∑i∈V​tanh(α⟨∏i​⟩)2]2

onde β=1/2\beta=1/2β=1/2, ν=∣E∣/2+(m−1)/4\nu = |E|/2 + (m -1) /4ν=∣E∣/2+(m−1)/4, ∣E∣|E|∣E∣ é o número de arestas, e mmm é o número de nós no grafo.

def loss_func_estimator(x, ansatz, hamiltonian, estimator, graph):
    """
    Calculates the specified loss function for the given ansatz, Hamiltonian,
    and graph.

    The expectation values of each Pauli string in the Hamiltonian are first
    obtained by running the ansatz on the quantum backend. These
    expectation values are then passed through the nonlinear function
    tanh(alpha * prod_i). The loss function is
    subsequently computed from these transformed values.
    """
    job = estimator.run(
        [
            (ansatz, hamiltonian[0], x),
            (ansatz, hamiltonian[1], x),
            (ansatz, hamiltonian[2], x),
        ]
    )
    result = job.result()

    # calculate the loss function
    node_exp_map = {}
    idx = 0
    for r in result:
        for ev in r.data.evs:
            node_exp_map[idx] = ev
            idx += 1

    loss = 0
    alpha = num_qubits
    for edge0, edge1 in graph.edge_list():
        loss += np.tanh(alpha * node_exp_map[edge0]) * np.tanh(
            alpha * node_exp_map[edge1]
        )

    regulation_term = 0
    for i in range(len(graph.nodes())):
        regulation_term += np.tanh(alpha * node_exp_map[i]) ** 2
    regulation_term = regulation_term / len(graph.nodes())
    regulation_term = regulation_term**2
    beta = 1 / 2
    v = len(graph.edges()) / 2 + (len(graph.nodes()) - 1) / 4
    regulation_term = beta * v * regulation_term

    loss = loss + regulation_term

    global experiment_result
    print(f"Iter {len(experiment_result)}: {loss}")
    experiment_result.append({"loss": loss, "exp_map": node_exp_map})
    return loss

Passo 4: Pós-processar e retornar resultado no formato clássico desejado​

As partições dos nós são determinadas avaliando o sinal dos valores esperados das strings de Pauli que codificam os nós. Um valor esperado não negativo atribui ao nó o valor 1, e um valor esperado negativo atribui 0. O método interpret de Maxcut então decodifica essa atribuição nos dois conjuntos de nós.

# Decode the node assignment from the iteration with the lowest loss.
# If the expectation value is non-negative, the node is assigned 1,
# otherwise it is assigned 0.
def get_bits(experiment_result):
    best_index = min(
        range(len(experiment_result)),
        key=lambda i: experiment_result[i]["loss"],
    )
    exp_map = experiment_result[best_index]["exp_map"]
    bits = [1 if exp_map[i] >= 0 else 0 for i in range(len(exp_map))]
    return bits, best_index

Uma vez que o treinamento está completo, realizamos uma rodada de busca de troca de bit único para melhorar a solução como uma etapa de pós-processamento clássico. Neste processo, trocamos as partições de dois nós e avaliamos o tamanho do corte. Se o tamanho do corte for melhorado, mantemos a troca. Repetimos este processo para todos os pares possíveis de nós conectados por uma aresta.

# Swap the partitions and calculate the cut size

def swap_partitions(graph, cur_bits, evaluate_cut):
    best_cut = 0
    best_bits = []
    for edge0, edge1 in graph.edge_list():
        swapped_bits = cur_bits.copy()
        swapped_bits[edge0], swapped_bits[edge1] = (
            swapped_bits[edge1],
            swapped_bits[edge0],
        )
        cut_size = evaluate_cut(swapped_bits)
        if best_cut < cut_size:
            best_cut = cut_size
            best_bits = swapped_bits
    return best_cut, best_bits

best_cut, best_bits = swap_partitions(graph, cur_bits, evaluate_cut)
