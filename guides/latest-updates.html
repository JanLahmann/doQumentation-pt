Maio de 2026​

  • Suporte para a instrução Store em QPUs da IBM® - Agora você pode simplificar computações clássicas complexas em seus circuitos quânticos com a instrução Store.

    • Calcule uma expressão clássica no meio do circuito e salve o resultado em uma variável ou registrador, que pode então controlar imediatamente gates quânticos subsequentes. Em vez de expressões inline profundamente aninhadas, você pode dividir as computações em etapas intermediárias nomeadas, para que a lógica de feedback clássico complexa seja mais fácil de ler e manter. Casos de uso comuns incluem os seguintes:

      • Circuitos dinâmicos com medições de circuito intermediário e feedback clássico
      • Preparação de entrelaçamento de longo alcance
      • Lógica condicional complexa baseada em resultados de medição

      Para usar a instrução store, primeiro certifique-se de estar executando a versão mais recente do qiskit-ibm-runtime (pip install --upgrade qiskit-ibm-runtime), e depois consulte a documentação para mais informações e um exemplo.

      Observe que antes de enviar jobs, você deve verificar a compatibilidade com as opções de cada primitivo na documentação: Opções do Sampler | Opções do Estimator | Opções do Executor

  • Novas Contas de Sala de Aula: Professores agora podem solicitar uma Conta de Sala de Aula para gerenciar e facilitar o acesso dos seus alunos. Com as Contas de Sala de Aula, os alunos podem usar os recursos do Plano Open sem precisar fornecer informações de cartão de crédito pessoal.

Descontinuação futura do serviço Qiskit Code Assistant​

Em 29 de maio de 2026, a IBM Quantum vai descontinuar o serviço de prévia do Qiskit Code Assistant e arquivar as extensões de suporte para Visual Studio Code e JupyterLab.

Com base no feedback e nos padrões de uso, mais usuários estão executando os modelos do Qiskit Code Assistant localmente e trabalhando em integrações de editor que já fazem parte do seu fluxo de trabalho de desenvolvimento.

Os modelos do Qiskit Code Assistant continuarão disponíveis para uso local. Para continuar usando-os, migre para uma implantação local e uma integração de editor com suporte da comunidade ou outra ferramenta local.

Para orientação de configuração, consulte o guia Qiskit Code Assistant.

Nighthawk chega à UE​

Os Planos Premium e Flex agora têm acesso antecipado ao ibm_berlin! É a primeira QPU IBM Quantum Nighthawk r1 na UE (região eu-de) e o segundo Nighthawk em nossa frota global, após o ibm_miami nos EUA (região us-east). O ibm_berlin apresenta gates de dois qubits mais rápidos do que o ibm_miami (68 ns versus 138 ns, mediana), mantendo coerência semelhante como líder de frota (T1_11​ de ~350 µs).

Desde seu lançamento, o Nighthawk tem possibilitado pesquisas em regimes onde a simulação clássica se torna cada vez mais desafiadora. Especificamente, sua arquitetura suporta fluxos de trabalho eficientes em hardware que se mapeiam naturalmente em modelos baseados em grade (rede). Veja artigos recentes da Phasecraft e da Volkswagen, e seus colaboradores, demonstrando simulação em escala no Nighthawk.

Por favor, observe que o ibm_berlin é atualmente uma QPU exploratória que ainda está sendo testada e otimizada como parte de nossos ciclos contínuos de aprendizado. Como tal, ele temporariamente possui as seguintes limitações:

  • O tempo de repetição padrão foi temporariamente aumentado de 250 µs para 4 ms, o que impacta o tempo de QPU necessário para executar cargas de trabalho. Os usuários podem selecionar manualmente um tempo de repetição menor, mas o desempenho pode ser degradado.
  • Circuitos dinâmicos ainda não são suportados, e a qualidade das medições de circuito intermediário é limitada.

Aumento no tempo máximo de atraso de repetição​

Para oferecer mais flexibilidade aos usuários, expandimos o intervalo permitido de tempo de atraso de repetição de 20-500 µs para 20-2000 µs em nossas QPUs Heron e Eagle. O intervalo de tempo de atraso da QPU Nighthawk continua sendo 1000-4000 µs conforme anunciado anteriormente. Observe que, se você optar por aumentar o atraso de repetição (rep_delay), isso terá um impacto direto no seu tempo de execução e no consumo de capacidade, mas pode melhorar a fidelidade de certos circuitos. O rep_delay padrão permanece inalterado em todas as QPUs.

Você pode encontrar mais informações sobre o tempo de atraso de repetição, incluindo como alterá-lo, em Inicialização de Qubit.

Qiskit SDK v2.3​

Janeiro de 2026​

  • Baseando-se no impulso estabelecido ao longo da série v2.x, que se concentrou em posicionar o Qiskit como a plataforma líder para fluxos de trabalho híbridos quântico-HPC, o Qiskit SDK v2.3 entrega uma expansão significativa da API C, juntamente com ferramentas mais rápidas e flexíveis para construir e otimizar circuitos quânticos.

    As principais atualizações incluem:

    • Passes de Transpiler personalizados em C - Escreva passes de Transpiler personalizados por meio da API C do Qiskit usando o novo objeto QkDag e um objeto QkTarget expandido, que permitem inspeção, modificação e extensão passo a passo do processo de compilação — sem reconstruir todo o pipeline do compilador.

    • Seleção de layout de hardware mais rápida - Atualizações e aprimoramentos de desempenho orientados por Rust em VF2Layout e VF2PostLayout melhoram a velocidade e a escalabilidade da seleção de layout de circuito para hardware, reduzindo o overhead de compilação e melhorando a fidelidade no hardware quântico.

    • Nova medição de Pauli multi-qubit - A nova instrução PauliProductMeasurement permite medição projetiva conjunta em múltiplos qubits em uma única operação, desbloqueando a compilação para computação baseada em Pauli — uma representação comum na computação quântica tolerante a falhas.

    • Melhorias na transpilação para tolerância a falhas inicial - Aprimoramentos de desempenho e recursos para transpilação voltada a alvos de tolerância a falhas iniciais — especialmente alvos Clifford+T — ajudam os usuários a construir pipelines de transpilação com mais eficiência para QPUs futuras.

    Essas capacidades oferecem aos desenvolvedores maior flexibilidade para personalizar otimizações de circuito quântico e integrar com fluxos de trabalho HPC existentes. Visite o blog para o resumo técnico completo.

  • Circuit functions

    • Q-CTRL está lançando uma circuit function que aplica técnicas de controle quântico baseadas em IA, com as quais os usuários podem escalar com sucesso para problemas maiores.
    • Algorithmiq está lançando uma circuit function que aplica TEM (tensor-network error mitigation), um método de mitigação de erros para obter estimadores com menos shots do que o método PEC (probabilistic error cancellation).
    • QEDMA está lançando uma circuit function que usa protocolos proprietários para caracterização eficiente e precisa das operações de QPU com ruído, e aplica supressão e mitigação de erros com base nos dados de caracterização.

  • Application functions

    • Q-CTRL está lançando um solver de otimização com o qual os usuários podem passar um grafo ou um objetivo e receber custos de solução.
